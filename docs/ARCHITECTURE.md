# Architecture

## What this repo is

`echo-protocol` is not the application — it's the provisioning codebase
for the Debian 12 server the application(s) run on. Running `install.sh`
against a fresh droplet turns it into a secured, fully-configured host
ready for Docker workloads, the Ruflo project, APIs, and general AI
development.

## Target host

| | |
|---|---|
| OS | Debian 12 (Bookworm), amd64 (x86_64) or arm64 (aarch64) |
| Sizing assumed by tuning defaults | 4 vCPU / 8 GB RAM / 100 GB NVMe (or larger — e.g. Oracle Cloud's Always Free Ampere A1 offers up to 4 OCPU/24GB/200GB free; see `docs/ORACLE-FREE-TIER.md`) |
| Network | Public static IPv4, IPv6 enabled |
| Exposed ports | 22 (SSH), 80 (HTTP), 443 (HTTPS) — everything else denied by UFW |

Architecture is auto-detected (`scripts/lib/common.sh`'s `detect_arch`)
— stages that fetch prebuilt binaries from upstream GitHub releases
(eza/zoxide/fastfetch in stage 06, Go in stage 09) resolve the correct
amd64/arm64 asset at install time rather than hardcoding one. Every
apt-installed package already ships both architectures upstream.

## Layered design

Provisioning is split into 18 numbered stages (`scripts/00-*.sh` through
`scripts/99-validate.sh`), each independently runnable and idempotent.
`install.sh` runs them in order; you can also re-run a single stage to
fix or update just that piece of the system. Stages build on each other
roughly like this:

```
00 bootstrap        OS updates, admin user, base directories
01 ssh-hardening     \
02 firewall           } perimeter — must land before you'd ever expose
03 fail2ban           } a service, so they run early
04 apparmor          /
05 kernel-hardening  sysctl + swap, applies once, independent of the rest
06 core-utilities    shell/CLI tooling everything else assumes is present
07 python            \
08 node               } language runtimes, independent of each other
09 go-rust-java       /
10 docker            containers — nginx/app stacks build on this
11 databases         host-level Postgres/Redis/SQLite
12 nginx-certbot     reverse proxy + TLS, fronts whatever Docker/host
                      services stages 10-11 provide
13 media-ai-tools    ffmpeg/imagemagick/gh, no dependents
14 monitoring-logging glances + persistent journald + logrotate
15 git-config        git identity + outbound SSH key for GitHub/GitLab
16 automation-cron   installs automation/ scripts + systemd timers —
                      depends on 00 (admin user), 10/11 (what it backs up)
99 validate          checks the output of every prior stage
```

## Two layers of SSH keys

Stage 00 installs `ADMIN_SSH_PUBKEY` (a key you generate on your own
machine) into the admin user's `authorized_keys` — this is how *you* log
in. Stage 15 generates a *separate* Ed25519 keypair
(`~/.ssh/id_ed25519_git`) on the server itself — this is how the server
authenticates *outbound* to GitHub/GitLab for `git clone`/`push` over
SSH. Don't confuse the two; see `docs/SSH.md` and `docs/GIT.md`.

## Where application workloads run

The host installs Postgres/Redis/SQLite directly (stage 11) for shared
tooling and anything you deliberately want outside a container, but the
intended pattern for actual applications is: one directory per project
under `~/docker/<project>/`, each with its own `docker-compose.yml`
(start from `docker/docker-compose.example.yml`) giving that project its
own disposable Postgres/Redis containers. Nginx (stage 12) reverse-proxies
by domain into whichever port each project's compose file publishes on
`127.0.0.1`. `~/ruflo` is reserved as the Ruflo project's directory and
already has a vhost slot rendered (`RUFLO_DOMAIN`) — no further specifics
about Ruflo were available at provisioning time, so this repo only
allocates the placeholder infrastructure for it.

## Automation layer

Stage 16 copies `automation/*.sh` to `~/scripts/automation/` and installs
three systemd timers (`docs/BACKUP-RESTORE.md`, `docs/MAINTENANCE.md`):

- `backup.timer` — daily, runs `backup-run.sh` (system config, Postgres,
  Redis, Docker volumes, project directories)
- `health-check.timer` — every 15 minutes, checks disk/mem/load/services/
  cert expiry, posts to a webhook on failure
- `maintenance.timer` — weekly, runs system update + cleanup + Docker
  cleanup

All automation scripts read shared config from
`/etc/echo-protocol/automation.env` (root-only, generated by stage 16
from `.env`) rather than depending on the repo checkout still being
present on disk.

## What this repo does *not* do

It does not provision the droplet itself (create the VM, attach a
DigitalOcean Spaces bucket, configure DNS) — that happens in the
DigitalOcean control panel / API / `doctl` / Terraform, outside this
repo's scope, before you point `install.sh` at the resulting host. It
also does not contain the Ruflo application code.
